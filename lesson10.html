API 概念與應用場景 (Concepts & Scenarios)

何謂 API？(Application Programming Interface)

API 中文為「應用程式介面」。它是串接兩端裝置或應用程式的橋樑，實現資訊或技術的交換與溝通。使用 API 能大幅減少開發成本，因為你不需要知道對方底層怎麼寫的，只需「傳送需求」，就能「取得結果」。

💡 業界最經典的比喻：餐廳的服務生
把你（Client 端）當作客人，廚房（Server 端後端系統）當作廚師。你不需要親自進廚房炒菜，你只需要把菜單交給服務生（API）；服務生會把你的點單翻譯給廚房聽，等廚房做好菜後，服務生再把餐點（Data）端回你的桌上。

現代網頁骨幹：Web API 與 RESTful 概念

Web API 是指專門藉由 HTTP 通訊協定，透過「網路」進行請求與回應的 API。現代 Web API 通常提供 JSON 傳輸格式，並且強烈建議遵循 RESTful 設計風格。

⚫ Web API 的兩大傳輸格式

  • JSON (現代主流)： 輕量、易讀，JavaScript 原生支援，解析速度極快。
  • XML (傳統標準)： 使用標籤包覆資料，結構嚴謹但較為冗長，多見於舊型企業系統（如銀行、政府老舊 API）。

⚫ RESTful API 基礎動詞

現代 Web API 會利用 HTTP 的「動詞」來對應資料庫的 CRUD 操作：

  • GET： 讀取資料 (Read)
  • POST： 新增資料 (Create)
  • PUT / PATCH： 更新資料 (Update)
  • DELETE： 刪除資料 (Delete)

💡 常見 Web API 實戰應用場景

現代網站很少從零開始自己做所有功能，多數強大且複雜的服務都是透過串接第三方 Web API 來實現的。

⚫ 身分驗證與社群整合 (OAuth)

  • 第三方快速登入： 網站常見的「使用 Google、LINE 或 Facebook 帳號登入」，就是串接該平台的認證 API。
  • 社群行為嵌入： 分享文章到臉書、讀取 Instagram 的貼文牆。

⚫ 數據獲取與第三方服務

  • 公開資料嵌入： 呼叫氣象局 API 顯示天氣、呼叫金融 API 獲取美股/台股即時報價、Google Maps 地圖嵌入。
  • 電子商務服務： 串接「綠界科技」或「LINE Pay」API 來處理信用卡結帳；串接超商物流 API 選擇取貨門市。

資料傳輸格式 (XML vs JSON)

為什麼 JSON 會成為現代 API 的霸主？

Web API 在傳輸資料時，需要一種前後端都「看得懂」的共通格式。早期流行 XML，但現在已經是 JSON 的天下。

⚫ 舊式標準：XML 格式

全名為「可延伸標記式語言」。

  • 缺點 1：冗長笨重。 每一筆資料都要用開頭與結尾的標籤包覆，導致傳輸檔案變得很大。
  • 缺點 2：解析麻煩。 在前端需要透過複雜的 DOM 操作才能把 XML 裡面的資料抽出來。

⚫ 現代主流：JSON 格式

全名為「JavaScript 物件表示法」。

  • 優點 1：輕量快速。 只保留單純的鍵值對 (Key-Value) 和陣列符號，檔案極小。
  • 優點 2：原生相容。 格式幾乎等同於 JavaScript 的物件，前端接手後可以「無縫接軌」直接使用。
  • 優點 3：跨語言支援。 PHP、Python、Java 都有極度完善的函式庫可一鍵解析 JSON。

實戰對照：XML 與 JSON 的語法差異

我們用同一筆「多拉A夢」的資料，來看看兩種格式在寫法上的差異。

⚫ XML 寫法 (像 HTML 一樣)

<robot>
    <name>多拉A夢</name>
    <height>129.3</height>
    <weight>129.3</weight>
    <hobby>
        <food>銅鑼燒、機油</food>
        <relationship>和小咪約會</relationship>
    </hobby>
</robot>

⚫ 🌟 JSON 寫法 (極度簡潔)

💡 語法限制： JSON 的 Key (鍵名) 必須使用雙引號 "" 包覆，且最後一筆資料後面不能有逗號。 
{
    "name": "多拉A夢",
    "height": 129.3,
    "weight": 129.3,
    "hobby": {
        "food": "銅鑼燒、機油",
        "relationship": "和小咪約會"
    }
}

💡 現代實戰：前端如何請求 JSON 資料？

前端要向後端 (或 API 端點) 要資料，我們稱為發送「非同步請求」。除了使用 jQuery 之外，現代開發更推崇原生內建的寫法。

⚫ 使用 jQuery AJAX (傳統經典)

透過 jQuery 幫我們處理掉底層複雜的 XMLHttpRequest。

// 簡易版 GET 請求 (取得 demo.json 的資料)
$.get("demo.json", function(result) {
    // jQuery 非常聰明，通常會自動幫你把 JSON 轉成 JS 物件
    console.log("jQuery 取得結果：", result);
    console.log("身高是：", result.height);
});

⚫ 🌟 使用原生 Fetch API (現代標準)

現代前端開發（不依賴 jQuery 時）絕對必學的寫法！基於 Promise 架構，處理非同步極度優雅。

// 現代瀏覽器內建的 fetch 寫法
fetch("demo.json")
    .then(response => response.json()) // 1. 將回應解析為 JSON
    .then(data => {
        // 2. 順利拿到 JS 物件資料
        console.log("Fetch 取得結果：", data);
        console.log("最愛食物：", data.hobby.food);
    })
    .catch(error => {
        console.error("請求發生錯誤：", error);
    });

前後端串接實作 (AJAX & PHP Endpoints)

後端實作：打造 GET 讀取 API (Read Data)

從資料庫撈出資料後，將它打包成 JSON 格式輸出給前端。這是製作 API 最基礎的流程。

💡 現代 API 必備起手式：宣告 Header
瀏覽器預設會把 PHP 輸出的內容當作「HTML 網頁」來解析。如果我們要輸出真正的 API，必須在程式最上方加上 header('Content-Type: application/json; charset=utf-8');，明確告訴前端這是一包 JSON 格式的數據。

⚫ 舊式寫法 (冗長且易錯)

過去常需要宣告一個計數器 $i，然後一行一行地把欄位塞進陣列裡。

<?php
    // ⚠️ 傳統繁瑣的組裝方式
    $i = 0;
    while ($row = $result->fetch_assoc()) {
        $data[$i]['id'] = $row['id'];
        $data[$i]['title'] = $row['title'];
        $data[$i]['content'] = $row['content'];
        $i++;
    }
?>

⚫ 現代 PHP 寫法 (極度簡潔)

直接把抓出來的一整列關聯陣列，推入結果陣列中。

<?php
    // 1. 宣告這是一個 JSON API
    header('Content-Type: application/json; charset=utf-8');
    require_once("db.php");

    $sql = "SELECT id, title, content FROM my_table";
    $result = mysqli_query($conn, $sql);
    
    $data = []; // 初始化空陣列
    
    // 2. 🌟 現代寫法：直接將整列資料推入陣列中
    while ($row = mysqli_fetch_assoc($result)) {
        $data[] = $row; 
    }

    // 3. 組合最終回應格式
    $response = [
        "success" => true,
        "data"    => $data
    ];

    // 4. 輸出 JSON
    echo json_encode($response, JSON_UNESCAPED_UNICODE);
?>

後端實作：打造 POST 寫入 API (Insert Data)

接收前端傳來的表單或檔案資料，寫入資料庫後，回傳「成功」或「失敗」的狀態訊息給前端。

⚫ 執行寫入與狀態回傳

根據 mysqli_query 的執行結果，動態改變要回傳的陣列內容。

<?php
    header('Content-Type: application/json; charset=utf-8');
    require_once("db.php");

    // 接收前端資料 (實務上請務必使用 Prepared Statements 防護)
    $user = $_POST['user'] ?? '';
    $file = $_FILES['photo']['name'] ?? '';

    $sql = "INSERT INTO my_table (user, photo) VALUES ('$user', '$file')";
    
    $response = []; // 準備回傳的陣列

    // 判斷是否寫入成功
    if (mysqli_query($conn, $sql)) {
        $response['success'] = true;
        $response['message'] = '資料傳送成功';
    } else {
        $response['success'] = false;
        $response['message'] = '資料傳送失敗';
    }
?>

⚫ 解決中文亂碼：JSON_UNESCAPED_UNICODE

預設情況下，json_encode 會把中文字轉成類似 \u8cc7\u6599 的 Unicode 編碼。加入這個常數參數就能保留原生中文！

<?php
    // ...接續左側邏輯...

    // 🌟 轉換為 JSON 字串，並保留原生中文
    $api_result = json_encode($response, JSON_UNESCAPED_UNICODE);
    
    // 輸出最終結果
    echo $api_result;
?>

💡 前端實作：AJAX 非同步請求與檔案上傳 (FormData)

如果表單內含有「圖片/檔案」需要上傳，我們就不能只傳送純文字 JSON，必須利用 JavaScript 內建的 FormData 物件來打包資料！

⚫ 1. 使用 FormData 打包資料

這個寫法可以完美模擬傳統 HTML 表單 enctype="multipart/form-data" 的行為。

// 建立一個空的表單資料物件
let formData = new FormData();

// 加入純文字資料
// 第一個參數是 Key (等同於 input 的 name)
formData.append('user', $('#guest').val());

// 🌟 加入檔案資料
// $('#photo')[0] 取得原生的 DOM 元素
// .files[0] 取得使用者選擇的第一個檔案實體
formData.append('photo', $('#photo')[0].files[0]);

⚫ 2. jQuery AJAX 關鍵參數設定

用 AJAX 傳送 FormData 時，有兩個參數「絕對必須」設為 false，否則會發生錯誤！

$.ajax({
    url: 'api_insert.php',
    type: 'POST',
    data: formData,
    // 🛡️ 檔案上傳必備的兩個 false：
    // 取消預設的內容編碼，讓瀏覽器自動加上 multipart 邊界
    contentType: false, 
    // 禁止 jQuery 把檔案轉換成查詢字串 (Query String)
    processData: false, 
    
    success: function(returnData) {
        // 如果後端有設 Header，這裡的 returnData 就會是 JS 物件
        if (returnData.success) {
            alert(returnData.message); // 顯示：資料傳送成功
        }
    }
});
