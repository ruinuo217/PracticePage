React 06: useEffect 生命週期

處理副作用與元件生命週期，掌握 useEffect 的三種用法

什麼是副作用（Side Effect）？

在 React 中，元件的主要工作是「根據資料渲染畫面」。但有些動作不屬於畫面渲染的範疇，這些就叫做副作用（Side Effect）。

常見的副作用包括：

  • 打 API 取得資料：向後端伺服器發送請求，取得要顯示的資料
  • 設定計時器：setTimeout、setInterval 等非同步操作
  • 訂閱事件：addEventListener 監聽滾動、視窗大小改變等
  • 操作 DOM：直接修改 document.title 或手動操控 DOM 節點
  • 存取 localStorage：將資料儲存到瀏覽器本地端

這些副作用都不應該直接寫在元件函式的最上層，因為每次渲染都會重新執行。 正確的做法是使用 useEffect Hook 來處理！

useEffect 基本語法與三種用法

useEffect 接受兩個參數：一個回呼函式和一個依賴陣列。

import { useEffect } from 'react';

// 基本語法
useEffect(() => {
  // 這裡放要執行的副作用
}, [依賴陣列]);

三種依賴陣列寫法：

1. 空陣列 []：只在元件「首次掛載」時執行一次（最常用！打 API 就是用這個） 

// 最常用：元件載入時打一次 API
useEffect(() => {
  fetch('/api/users')
    .then(res => res.json())
    .then(data => setUsers(data));
}, []);  // 空陣列 = 只執行一次

2. 有依賴 [count]：當 count 改變時才執行 

// count 改變時，更新網頁標題
useEffect(() => {
  document.title = `你點了 ${count} 次`;
}, [count]);  // count 改變時才執行

3. 不寫依賴陣列：每次渲染都會執行（幾乎不用，容易造成無限迴圈！） 

// 幾乎不用！每次渲染都會執行
useEffect(() => {
  console.log('元件重新渲染了');
});  // 沒有第二個參數

Cleanup 清除副作用

useEffect 回呼函式可以 return 一個函式，這個函式會在元件「卸載（消失）」時自動執行， 用來清除先前設定的副作用，避免記憶體洩漏（memory leak）。 

useEffect(() => {
  // 設定副作用
  const timer = setInterval(() => {
    console.log('每秒執行一次');
  }, 1000);

  // Cleanup：元件消失時清除計時器
  return () => {
    clearInterval(timer);
    console.log('計時器已清除！');
  };
}, []);

常見需要 Cleanup 的場景：

  • clearInterval / clearTimeout：清除計時器，避免元件消失後還在執行
  • removeEventListener：取消事件監聽，避免重複綁定
  • 取消 API 請求：使用 AbortController 取消尚未完成的請求
  • WebSocket 斷線：關閉 WebSocket 連線
// Cleanup 範例：監聽視窗大小
useEffect(() => {
  const handleResize = () => {
    setWidth(window.innerWidth);
  };
  window.addEventListener('resize', handleResize);

  return () => {
    window.removeEventListener('resize', handleResize);
  };
}, []);

完整範例：useEffect + setInterval 計時器

以下是一個完整的倒數計時器元件，展示 useEffect 搭配 setInterval 和 cleanup 的用法： 

import { useState, useEffect } from 'react';

function CountdownTimer({ initialSeconds = 60 }) {
  const [seconds, setSeconds] = useState(initialSeconds);
  const [isRunning, setIsRunning] = useState(false);

  useEffect(() => {
    // 如果沒有在運行，或已經倒數到 0，就不啟動計時器
    if (!isRunning || seconds <= 0) return;

    // 設定每秒倒數的計時器
    const timer = setInterval(() => {
      setSeconds(prev => {
        if (prev <= 1) {
          setIsRunning(false);  // 倒數結束，停止
          return 0;
        }
        return prev - 1;
      });
    }, 1000);

    // Cleanup：元件卸載或依賴改變時，清除計時器
    return () => clearInterval(timer);
  }, [isRunning, seconds]);

  // 重設倒數
  const handleReset = () => {
    setIsRunning(false);
    setSeconds(initialSeconds);
  };

  return (
    <div className="timer-card">
      <h2>⏱ 倒數計時器</h2>
      <p className="timer-display">{seconds} 秒</p>
      <button onClick={() => setIsRunning(true)} disabled={isRunning}>
        開始
      </button>
      <button onClick={() => setIsRunning(false)} disabled={!isRunning}>
        暫停
      </button>
      <button onClick={handleReset}>重設</button>
    </div>
  );
}

export default CountdownTimer;

重點觀察：依賴陣列中放了 [isRunning, seconds]， 表示當 isRunning 或 seconds 改變時，舊的 setInterval 會先被 cleanup 清除， 然後再建立新的 setInterval。這確保了計時器行為的正確性。

useEffect 依賴陣列記憶口訣

useEffect(() => { }, [])
空陣列 [] → 只跑一次（掛載時）→ 最常用來打 API

useEffect(() => { }, [count])
有依賴 [變數] → 變數改變才跑 → 同步更新相關資料

useEffect(() => { })
沒寫陣列 → 每次渲染都跑 → 幾乎不用，小心無限迴圈！

口訣：「空一次、有變跑、沒寫全都跑」
